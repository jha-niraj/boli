    Running Python with uv

    Before any syntax: where Python lives on your Mac, what uv does, and the three ways you will run code.

    Why this matters for Boli

    Everything in ml/ runs through uv. If you understand this lesson, "it works on my machine" problems become easy to fix.

    You already know this shape

    uv is to Python what pnpm is to Node. The names change, the ideas don't.

    Node / TypeScriptPython with uvWhat it is
    package.jsonpyproject.tomlProject name, dependencies, tool settings
    pnpm-lock.yamluv.lockExact versions of everything installed
    node_modules/.venv/The project's private installed packages (a virtual environment)
    .nvmrc.python-versionWhich language version to use (ours says 3.12)
    pnpm installuv syncInstall what the lock file says
    pnpm add zoduv add soxrAdd a dependency
    pnpm exec tsx script.tsuv run python script.pyRun a file using the project's packages

    Why not just type python?

    Your Mac has a system Python 3.14 from Homebrew. It has none of our packages, and the speech libraries don't support 3.14 yet. uv run always uses the project's Python 3.12 and its .venv. Rule of thumb: inside ml/, start every command with uv run.

    shell
    cd ml
uv run python --version        # Python 3.12.x  (the project's)
python3 --version              # Python 3.14.x  (the system's, don't use it here)
uv run python -c "import numpy; print(numpy.__version__)"   # works: numpy is in .venv

    Three ways to run Python

    1. The REPL: an interactive prompt, like Node's node prompt. Perfect for "what does this return?"
    2. A script: a .py file you run top to bottom.
    3. Tests: uv run pytest finds and runs test_*.py files (Lesson 8).
    shell
    $ uv run python
>>> 16000 * 2.5
40000.0
>>> name = "Boli"
>>> f"hello {name}"
'hello Boli'
>>> help(len)          # built-in documentation for anything
>>> exit()             # or Ctrl+D

    The REPL prints the value of the last expression automatically. A script doesn't: there you need print(...).

    This confuses everyone

    Indentation is the syntax

    Python has no { } for blocks. The indentation (4 spaces) is the block. Mixing tabs and spaces, or indenting one line by 3, is a real error, not a style issue.

    "ModuleNotFoundError: No module named 'numpy'"

    Almost always means you ran the system python3 instead of uv run python. Same cause as running a Node script outside the folder that has node_modules.

    Lesson 1 · about 60 min

    Values, numbers and strings

    Variables, the basic types, f-strings, None, truthiness, and what Devanagari looks like inside a string.

    Why this matters for Boli

    Transcripts are strings, durations are floats, sample rates are ints. And the Devanagari part of this lesson is exactly what your normalise_devanagari function will deal with in Phase 1.

    Variables and types

    TypeScript
    ts
    const sampleRate: number = 16000;
let seconds = 2.5;
const name: string = "Boli";
const ready: boolean = true;
const nothing = null;
    Python
    python
    sample_rate: int = 16000
seconds = 2.5
name: str = "Boli"
ready: bool = True
nothing = None
    • No const/let. You just assign. By convention, ALL_CAPS names are treated as constants.
    • Names use snake_case, not camelCase.
    • True, False, None are capitalised. None replaces both null and undefined.
    • Type hints (: int) are like TS types but not checked when the code runs. They are documentation plus editor help.

    Numbers: int and float are different types

    TypeScript has one number. Python has int (whole, any size) and float (decimal).

    python
    frames = 40000            # int
sample_rate = 16000       # int
frames / sample_rate      # 2.5      "/" always gives a float
frames // sample_rate     # 2        "//" floor division: rounds DOWN to an int
frames % sample_rate      # 8000     remainder
2 ** 10                   # 1024     power (TS uses ** too)
int("27")                 # 27       string to int
float("4.25")             # 4.25
round(4.256, 2)           # 4.26

    Strings and f-strings

    An f-string is Python's template literal. Put f before the quotes and use { }. After a colon you can format: :.2f means "2 decimal places".

    TypeScript
    ts
    const id = "01-001";
const secs = 4.256;
`${id}: ${secs.toFixed(2)} s`
// "01-001: 4.26 s"
    Python
    python
    clip_id = "01-001"
secs = 4.256
f"{clip_id}: {secs:.2f} s"
# '01-001: 4.26 s'
    python
    text = "म आज meeting मा late हुन्छु।"
len(text)                 # number of characters (code points)
text.split()              # ['म', 'आज', 'meeting', 'मा', 'late', 'हुन्छु।']  split on whitespace
text.upper()              # only changes the Latin letters
"meeting" in text         # True   (like text.includes("meeting"))
text.startswith("म")      # True
text.replace("।", "")     # remove the danda
"03-027"[3:]              # '027'  slicing, covered properly in Lesson 2
"  hi  ".strip()          # 'hi'   (like trim())

    Devanagari inside a string

    A string is a sequence of Unicode code points. What you see as one Nepali letter is often several code points. नमस्ते is 6 code points: न, म, स, ् (halant), त, े (the vowel sign).

    python
    word = "नमस्ते"
len(word)                          # 6
[hex(ord(ch)) for ch in word]      # ['0x928', '0x92e', '0x938', '0x94d', '0x924', '0x947']
"न"                           # 'न'  write a code point by its number

import unicodedata
unicodedata.name("्")              # 'DEVANAGARI SIGN VIRAMA'

    The same visible text can be stored in two ways. क़ can be one code point (U+0958) or two (क + the nukta dot U+093C). They look identical but == says they're different. NFC normalisation converts both to one agreed form, which is why the eval harness normalises before comparing:

    python
    a = "क़"            # क़ as one code point
b = "क़"      # क + nukta
a == b                                                   # False
unicodedata.normalize("NFC", a) == unicodedata.normalize("NFC", b)   # True

    Truthiness and None

    Like JavaScript, values are "truthy" or "falsy" in an if. The falsy ones: False, None, 0, 0.0, "", and empty containers like [] and {}. Everything else is truthy, including the string "0".

    python
    transcript = ""
if not transcript:             # Python uses "not", "and", "or" instead of !, &&, ||
    print("model returned nothing")

result = None
if result is None:             # compare to None with "is", not "=="
    print("no result yet")
    This confuses everyone

    / vs //

    7 / 2 is 3.5, 7 // 2 is 3. And floor means down: -7 // 2 is -4, not -3.

    round() rounds halves to the even number

    round(2.5) is 2 and round(3.5) is 4. This is "banker's rounding". It avoids bias over many numbers, but surprises everyone the first time.

    Strings can't change

    text.replace(...) returns a new string. Writing text.replace("।", "") on its own line does nothing; you need text = text.replace("।", "").

    len() counts code points, not what you see

    For Nepali, "letters you see" and len() rarely agree. It doesn't matter for scoring, but it will surprise you when you slice Devanagari strings.

    Lists, dicts, tuples and sets

    The four containers, slicing, and the comprehension: the single most Python-looking thing you'll write.

    Why this matters for Boli

    An eval run is a list of clips, each clip a dict of fields, and the results a dict of model name to scores. You'll write these shapes every day in Phase 1.

    The four containers

    PythonClosest TSExampleUse it for
    listArray[4.2, 3.1, 5.0]Ordered items you add to
    dictobject / Map{"01-001": 4.2}Look up a value by key
    tuplereadonly tuple [number, number](3, 27)A fixed little group that won't change
    setSet{"quiet", "noisy"}Unique items, fast "is it in here?"

    Lists

    python
    durations = [4.2, 3.1, 5.0]
durations.append(2.4)        # push
len(durations)               # 4
durations[0]                 # 4.2   first
durations[-1]                # 2.4   last: negative indexes count from the end
sum(durations)               # 14.7
max(durations)               # 5.0
sorted(durations)            # [2.4, 3.1, 4.2, 5.0]  new list
durations.sort()             # sorts in place, returns None

    python

clips[-2:]       # ['d', 'e']        last two
clips[::2]       # ['a', 'c', 'e']   every second item
"03-027"[:2]     # '03'
"03-027"[3:]     # '027'

    Python

    Tuples and sets

    python

    Comprehensions: map and filter in one line

    A comprehension builds a new list (or dict, or set) from another. Read it left to right as "give me this, for each item, if that".

    TypeScript
    ts
    const long = Object.entries(clips)
  .filter(([id, s]) => s > 4)
  .map(([id]) => id);
    Python
    python
    long = [clip_id
        for clip_id, s in clips.items()
        if s > 4]
    python
    ms = [s * 1000 for s in durations]                        # map
words = {clip_id: len(t.split()) for clip_id, t in texts.items()}   # dict comprehension
devanagari_only = [w for w in text.split() if not w.isascii()]      # filter out English words
    This confuses everyone

    list.sort() returns None

    x = durations.sort() makes x equal to None. Use sorted(durations) when you want a new list back.

    in on a dict checks keys only

    40.6 in wer is False even though 40.6 is a value. Use 40.6 in wer.values().

    Assignment never copies

    b = a makes two names for the same list, exactly like JS. Change one and you change "both". Use b = list(a) or a.copy() for a real copy.

    {} is an empty dict, not an empty set

    Write set() for an empty set.

    Lesson 3 · about 50 min

    Functions and type hints

    def, default and keyword arguments, returning several values, docstrings, and the default-argument trap.

    Why this matters for Boli

    Every exercise you write in this project is a typed function with a docstring and a test. The working agreement says "type hints everywhere".

    Defining a function

    TypeScript
    ts
    function framesToSeconds(
  frames: number,
  sampleRate = 16000,
): number {
  return frames / sampleRate;
}
    Python
    python
    def frames_to_seconds(
    frames: int,
    sample_rate: int = 16_000,
) -> float:
    return frames / sample_rate
    • -> float is the return type. 16_000 is just 16000; underscores make big numbers readable.
    • A function with no return returns None (like undefined in JS).

    Keyword arguments

    Any argument can be passed by name. This is how Python code stays readable without an options object.

    python
    frames_to_seconds(40000)                       # 2.5
frames_to_seconds(40000, 8000)                 # 5.0
frames_to_seconds(40000, sample_rate=8000)     # 5.0, and clearer to read
frames_to_seconds(sample_rate=8000, frames=40000)   # order doesn't matter by name

    Docstrings

    The first string inside a function is its documentation. help(fn) in the REPL shows it, and your editor shows it on hover.

    python
    def real_time_factor(processing_seconds: float, audio_seconds: float) -> float:
    """How long processing took compared with the audio length.

    0.1 means 10 s of audio took 1 s to transcribe. Lower is faster.
    """
    if audio_seconds <= 0:
        raise ValueError(f"audio_seconds must be positive, got {audio_seconds}")
    return processing_seconds / audio_seconds

    Returning several values

    Return a tuple and unpack it at the call site.

    python
    def split_clip_id(clip_id: str) -> tuple[int, int]:
    part, sentence = clip_id.split("-")
    return int(part), int(sentence)

part, sentence = split_clip_id("03-027")    # part = 3, sentence = 27

    Type hints you'll use

    HintMeansTS equivalent
    list[float]a list of floatsnumber[]
    dict[str, float]string keys, float valuesRecord<string, number>
    tuple[int, int]exactly two ints[number, number]
    str | Nonea string or Nonestring | null
    Patha filesystem path (Lesson 5)-
    This confuses everyone

    The mutable default argument

    Default values are created once, when the function is defined, not on every call. A list default is shared between calls:

    python
    def add_clip(clip, clips=[]):      # BUG: one list shared by every call
    clips.append(clip)
    return clips

add_clip("a")    # ['a']
add_clip("b")    # ['a', 'b']   surprise!

def add_clip(clip, clips: list | None = None):   # the fix
    if clips is None:
        clips = []
    clips.append(clip)
    return clips

    Type hints don't stop wrong types

    frames_to_seconds("abc") runs and then crashes inside the function. Hints help you and your editor; they are not runtime checks like zod.

    Control flow, errors and stack traces

    if, for, while, enumerate and zip, raising and catching errors, and reading a stack trace calmly.

    Why this matters for Boli

    Model libraries throw long, scary errors. Reading the trace from the bottom up turns a 60-line wall of text into one line you can act on.

    if / elif / else

    python
    if wer < 20:
    verdict = "good"
elif wer < 40:              # "elif", not "else if"
    verdict = "usable"
else:
    verdict = "poor"

verdict = "good" if wer < 20 else "poor"     # the ternary: a if condition else b

    Loops

    Python's for is always a "for...of": it loops over items. There's no for (let i = 0; ...).

    python
    for clip_id in clip_ids:
    print(clip_id)

for i, clip_id in enumerate(clip_ids):       # need the index too? enumerate
    print(i, clip_id)

for ref, hyp in zip(references, hypotheses): # walk two lists side by side
    print(ref == hyp)

for i in range(3):                           # 0, 1, 2
    print(i)

while retries < 3:
    retries += 1                             # no ++ in Python

    Raising and catching errors

    TypeScript
    ts
    try {
  const s = parseFloat(text);
  if (isNaN(s)) throw new Error("bad");
} catch (e) {
  console.log(e);
} finally {
  cleanup();
}
    Python
    python
    try:
    s = float(text)
except ValueError as e:
    print(e)
finally:
    cleanup()
    • Catch the specific error you expect (ValueError, FileNotFoundError). A bare except: hides real bugs.
    • Common built-in errors: ValueError (right type, bad value), TypeError (wrong type), KeyError (missing dict key), IndexError (list too short), FileNotFoundError, ZeroDivisionError.
    • Raise your own with raise ValueError("clear message"), and include the bad value in the message.

    Reading a stack trace

    Start at the last line. It names the error and the message. Then walk up to find the first frame that is in your file; that's usually where to look.

    trace
    Traceback (most recent call last):                      ← "most recent LAST": read bottom up
  File "ml/practice/lesson_04/test_broken.py", line 9, in test_empty
    assert average_duration([]) == 0.0                  ← the test that called it
  File "ml/practice/lesson_04/broken.py", line 12, in average_duration
    return total / len(durations)                       ← YOUR line that crashed
ZeroDivisionError: division by zero                     ← START HERE: what went wrong
    1. Last line: ZeroDivisionError, so something was divided by 0.
    2. Frame above it: broken.py line 12, total / len(durations). So len(durations) was 0.
    3. Frame above that: the test passed []. Now you know the fix: handle the empty list first.

    With library errors (NeMo, torch), the bottom lines are deep inside the library. Keep walking up until you reach a file in our repo.

    This confuses everyone

    range(1, 5) stops before 5

    It gives 1, 2, 3, 4. And range(1, len(x)) skips the first item, a classic off-by-one bug. You'll find exactly that bug in this lesson's practice.

    Swallowing errors

    except Exception: pass makes failures silent. In an eval harness, a silently skipped clip changes the WER and nobody notices. Catch narrowly and record what failed.

    Lesson 5 · about 50 min

    Files, paths and with

    pathlib, reading and writing text safely, context managers, and JSON Lines manifests.

    Why this matters for Boli

    Every dataset in the harness is described by a manifest: a JSONL file with one clip per line. You'll read and write these constantly, with Devanagari text inside.

    Paths with pathlib

    A Path is an object, not a string. The / operator joins parts, like path.join in Node.

    python
    from pathlib import Path

root = Path("ml/eval/datasets")
manifest = root / "neptel" / "manifest.jsonl"     # join with /
manifest.name          # 'manifest.jsonl'
manifest.stem          # 'manifest'
manifest.suffix        # '.jsonl'
manifest.parent        # Path('ml/eval/datasets/neptel')
manifest.exists()      # True or False
sorted(root.glob("*/*.wav"))      # all WAVs one folder down
manifest.parent.mkdir(parents=True, exist_ok=True)    # like mkdir -p

    Reading and writing text

    python
    text = Path("part-01.md").read_text(encoding="utf-8")
Path("out.txt").write_text("नमस्ते\n", encoding="utf-8")

    Always pass encoding="utf-8". It is the default on a Mac but not everywhere, and Devanagari breaks first when it's wrong.

    with: the context manager

    For files you read line by line, use open inside a with block. A context manager guarantees cleanup (closing the file) when the block ends, even if an error happens inside. It's a try/finally you can't forget.

    Without with (don't)
    python
    f = open(path, encoding="utf-8")
try:
    for line in f:
        print(line)
finally:
    f.close()
    With with (do)
    python
    with open(path, encoding="utf-8") as f:
    for line in f:
        print(line)
# closed here automatically

    JSON and JSON Lines

    A JSONL file has one JSON object per line. It's easy to append to, and a broken line only breaks one clip.

    jsonl
    {"id": "01-001", "audio": "own/01-001.wav", "text": "बिहान उठेर मैले चिया बनाएँ।", "seconds": 3.8}
{"id": "07-001", "audio": "own/07-001.wav", "text": "म आज meeting मा late हुन्छु।", "seconds": 3.1}
    python
    import json

with open(path, encoding="utf-8") as f:
    rows = [json.loads(line) for line in f if line.strip()]   # skip blank lines

with open(path, "w", encoding="utf-8") as f:
    for row in rows:
        f.write(json.dumps(row, ensure_ascii=False) + "\n")

    ensure_ascii=False keeps Devanagari readable in the file. Without it, नमस्ते is saved as नम...: still valid, but impossible to read.

    This confuses everyone

    Relative paths depend on where you run the command

    Path("tests/x.wav") means "relative to the current terminal folder", not to the Python file. When a file "isn't found" but you can see it, check which folder you ran the command from.

    "w" wipes the file

    Opening with mode "w" empties the file immediately. Use "a" to append.

    Lesson 6 · about 50 min

    Classes and dataclasses

    How Python classes work, and why we use @dataclass for almost every record in the project.

    Why this matters for Boli

    Your first exercise returns an AudioInfo dataclass. Clips, eval results and model configs will all be dataclasses: typed records that are easy to print and compare.

    A plain class

    TypeScript
    ts
    class Clip {
  constructor(
    public id: string,
    public seconds: number,
  ) {}
  get minutes(): number {
    return this.seconds / 60;
  }
}
    Python
    python
    class Clip:
    def __init__(self, id: str, seconds: float) -> None:
        self.id = id
        self.seconds = seconds

    @property
    def minutes(self) -> float:
        return self.seconds / 60
    • __init__ is the constructor. self is this, but it is written out as the first parameter of every method.
    • @property makes a method readable like a field: clip.minutes, no brackets.
    • You create an object without new: Clip("01-001", 4.2).

    The dataclass: a typed record

    @dataclass writes __init__, a readable print form and == comparison for you, from the field list. Think "a TS interface that can also build the object".

    python
    from dataclasses import dataclass

@dataclass(frozen=True)          # frozen: fields can't be changed after creation
class AudioInfo:
    sample_rate: int
    channels: int
    num_frames: int
    duration_seconds: float

info = AudioInfo(sample_rate=16000, channels=1, num_frames=40000, duration_seconds=2.5)
info                       # AudioInfo(sample_rate=16000, channels=1, num_frames=40000, duration_seconds=2.5)
info.sample_rate           # 16000
info == AudioInfo(16000, 1, 40000, 2.5)    # True: compares field by field
info.channels = 2          # error: FrozenInstanceError

    Validation, properties and alternative constructors

    python
    @dataclass(frozen=True)
class Clip:
    id: str
    text: str
    seconds: float

    def __post_init__(self) -> None:
        # runs right after the generated __init__: the place to validate
        if self.seconds <= 0:
            raise ValueError(f"{self.id}: seconds must be positive")

    @property
    def word_count(self) -> int:
        return len(self.text.split())

    @classmethod
    def from_dict(cls, d: dict) -> "Clip":
        # cls is the class itself, so this works for subclasses too
        return cls(id=d["id"], text=d["text"], seconds=float(d["seconds"]))

clip = Clip.from_dict({"id": "01-001", "text": "म घर जाँदैछु।", "seconds": 2.1})
    This confuses everyone

    Forgetting self

    Every method's first parameter must be self, and inside the method you must write self.seconds, never just seconds. Forgetting it gives "takes 0 positional arguments but 1 was given".

    Mutable defaults again

    A dataclass field can't default to []. Use field(default_factory=list); it's the same trap as Lesson 3.

    Lesson 7 · about 40 min

    Modules, packages and imports

    How import finds code, what __init__.py is, and the mysterious if __name__ == "__main__".

    Why this matters for Boli

    ml/ is a package called boli_ml. The eval harness will be modules inside it, and you'll run them with python -m.

    Files are modules, folders are packages

    • A module is one .py file. boli_ml/audio.py is the module boli_ml.audio.
    • A package is a folder with an __init__.py file, like a folder with an index.ts.
    TypeScript
    ts
    import { audioInfo } from "./audio";
import * as np from "numpy-ish";
import fs from "node:fs";
    Python
    python
    from boli_ml.audio import audio_info
import numpy as np
import json

    How Python finds an import

    Python searches a list of folders called sys.path, in order: the folder of the script being run, the standard library, then the packages in .venv. That's why uv run matters: it puts our .venv on the path.

    python
    import sys
for p in sys.path:
    print(p)          # try it: uv run python -c "import sys; print(sys.path)"

    if __name__ == "__main__":

    Every module has a variable __name__. When you run the file directly, it is "__main__". When the file is imported, it's the module's name. So this block runs only when you run the file, never when something imports it.

    python
    def main() -> None:
    print("running as a script")

if __name__ == "__main__":
    main()

    Run a module from the project root with -m: uv run python -m boli_ml.audio file.wav. Using -m (not a file path) means imports resolve from the project root, the same way tests see them.

    Adding a dependency

    shell
    uv add jiwer            # adds to pyproject.toml, updates uv.lock, installs into .venv
uv add --dev ruff       # a dev-only dependency
uv remove jiwer
    This confuses everyone

    Naming a file after a library

    If you create numpy.py or json.py in your folder, import numpy loads your file instead of the real library, because the script's folder comes first in sys.path.

    "attempted relative import with no known parent package"

    You ran a file inside a package by its path. Run it with -m and the dotted module name instead.

    Testing with pytest

    Plain assert, temporary files, parametrized tests, comparing floats, expecting errors, and writing the test first.

    Why this matters for Boli

    "Measure everything" starts here. The regression test that guards our WER in Phase 2 is just a pytest test. In this lesson's practice, you write the tests yourself.

    The smallest test

    pytest finds files named test_*.py and runs functions named test_*. A plain assert is the whole API; when it fails, pytest shows both sides.

    vitest
    ts
    import { expect, test } from "vitest";

test("frames to seconds", () => {
  expect(framesToSeconds(40000)).toBe(2.5);
});
    pytest

    Lesson 9 · about 60 min

    NumPy: audio as numbers

    What a sound file is inside the computer, and how NumPy arrays let you work with millions of samples at once.

    Why this matters for Boli

    Every model in the project takes a NumPy array of audio samples. Sample rate, channels and duration from your first exercise are all just facts about this array.

    Sound is a list of numbers

    A microphone measures air pressure many times per second. Each measurement is a sample, a number between -1.0 and 1.0. The sample rate is how many per second: 16,000 for speech models, 44,100 for music. So 2 seconds of 16 kHz audio is 32,000 numbers.

    TermMeaningExample
    sample ratesamples per second, per channel16000
    channels1 = mono, 2 = stereo1
    frameone sample from every channel at one momentstereo: 2 numbers
    durationframes ÷ sample rate32000 ÷ 16000 = 2.0 s
    bit depthhow each sample is stored on disk16-bit: whole numbers from -32768 to 32767

    NumPy arrays

    A NumPy array is like a typed array (Float32Array) that can have several dimensions, and where maths applies to every element at once. That last part is called vectorisation, and it's thousands of times faster than a Python loop.

    python
    import numpy as np

samples = np.array([0.0, 0.5, -0.5, 0.25], dtype=np.float32)
samples.shape        # (4,)        one dimension: 4 samples, mono
samples.dtype        # float32
samples * 2          # array([ 0. ,  1. , -1. ,  0.5])   every element at once
np.abs(samples).max()    # 0.5     the loudest sample
samples[1:3]         # slicing works like lists

    Making a sound: a sine wave

    python
    sample_rate = 16_000
seconds = 1.0
t = np.arange(int(sample_rate * seconds)) / sample_rate   # the time of each sample: 0, 1/16000, 2/16000 ...
wave = 0.5 * np.sin(2 * np.pi * 440 * t)                  # a 440 Hz tone (the note A)
wave.shape                                                # (16000,)

import soundfile as sf
sf.write("tone.wav", wave, sample_rate)      # play it with: open tone.wav

    Stereo is a 2D array

    soundfile gives stereo audio as shape (frames, channels): one row per moment, one column per channel. Speech models want mono, so you average the columns.

    python
    data, sr = sf.read("song.wav")    # data.shape == (88200, 2) for 2 s stereo at 44.1 kHz
data.shape[0] / sr                # 2.0   duration: frames are the FIRST dimension
mono = data.mean(axis=1)          # average across channels → shape (88200,)
# axis=1 means "collapse the columns". axis=0 would average over time instead.

    Why 16 kHz, and what resampling is

    Human speech carries most of its meaning below 8 kHz, and a sample rate captures frequencies up to half its value. So 16 kHz is enough for speech and keeps the arrays small. Resampling converts audio from one rate to another properly (not by just dropping samples); in Boli we use the soxr library for it.

    This confuses everyone

    len() of a stereo array is the frame count

    len(data) gives the first dimension: frames, not samples. Use data.shape to see everything at once.

    int16 vs float32

    On disk, 16-bit audio is whole numbers up to 32767. soundfile converts to floats between -1 and 1 by default. If you ever see audio values like 12000, you're looking at int16 data.

    axis

    Read axis=1 as "the dimension that disappears". Shape (88200, 2) with axis=1 becomes (88200,).
