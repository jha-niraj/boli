1. The shape of a Go file

Every file starts with a package clause (package boli). Then come the imports, if any, then top-level declarations in any order: const, var, type and func. Comments are // or /* */. A comment right above a declaration is its doc comment: go doc and your editor show it, and by convention it starts with the name it documents.

There are no semicolons. The compiler adds them at the end of lines for you, which is why an opening brace { must sit on the same line as its if, for or func.

3. Constants

Constants are fixed at compile time: numbers, strings and booleans only (no slices or structs, which is why Models is a var). An untyped constant like DefaultMaxTokens is just "the number 1024" until it meets a typed value, so it fits into an int field or an int64 field without a conversion. A parenthesised block groups several declarations; it works for const, var, import and type.

6. Slices: Go's arrays

An array has a fixed length that is part of its type ([3]int), and you will rarely use one. A slice ([]int) is the growable list you use everywhere, like a TS array. Under the hood a slice is a small header with three fields: a pointer to an array, a length and a capacity.

len(s) is how many elements it has, cap(s) how many fit before append must allocate a bigger array and copy. s[1:3] is a new view of elements 1 and 2 (end excluded), still sharing memory. A nil slice (var s []string) has length 0 and works with len, range and append, so you almost never need to check for nil.

7. Maps

map[K]V is a hash map, like a TS Record or Map. Reading a missing key does not fail: it returns V's zero value, which is why you use ok when "missing" and "zero" mean different things. delete(m, k) removes, len(m) counts. Iteration order is deliberately random on every run, so never depend on it. Writing to a nil map (var m map[string]int with no make) panics.

8. Structs

A struct is a named group of fields, the closest thing to a TS object type, but it is a real type with a fixed set of fields: you cannot add a field at run time. Fields you leave out of a literal get their zero value. Read fields with a dot: m.PricePerMillion.Input.

9. Values, copies and pointers

Go passes everything by value: assigning or passing a struct copies it. That is different from TS, where objects are always shared references.

Use a pointer when a function must change the caller's value, or when a struct is large and copying it on every call is wasteful. CostMicro takes m Model by value because it only reads it. There is no pointer arithmetic in Go, so pointers are safe to use.

10. Named types and methods

ErrorCode is like the TS union keyof typeof API_ERRORS, but looser: Go has no union of string literals, so any string can be converted with ErrorCode("typo"). The named type still stops you passing a random string variable by accident, and it lets us attach methods. Any named type you define can have methods, not just structs. Go has no classes: a type plus its methods is the whole idea.

11. Strings are bytes (this matters for Nepali)

In JavaScript "नेपाल".length is 5 (UTF-16 code units). In Go len counts bytes. Any limit like "name at most 64 characters" must decide which one it means. The TS zod .max(64) counts UTF-16 units, and Chapter 3 will match that exactly.

TypeScript vs Go

Why no Math.ceil? In TS number is a float, so the ceil guards against a fractional price. Our prices are whole micro-credits per token, so in int64 the result is already whole. The comment in boli.go says what must change if a price ever becomes fractional: integer ceiling division, never floats.

Traps

  1. := in an inner block makes a NEW variable that hides the outer one. n := 10; if n := 5; n > 1 { } leaves the outer n at 10. This bites hardest with err.
  2. Integer division truncates toward zero. 7/2 is 3 and -7/2 is -3. Convert to float64 first if you want 3.5.
  3. Integers overflow silently. An int8 at 127 plus 1 becomes -128 with no error. Use int64 for money and token counts.
  4. Writing to a nil map panics. var m map[string]int; m["x"] = 1 crashes. Create it with make(map[string]int) or a literal. Reading a nil map is fine.
  5. for _, m := range models gives you a COPY. m.ID = "x" changes the copy, not the slice. Use the index: models[i].ID = "x".
  6. append may or may not reuse the array. If two slices share an array and one appends within capacity, the other sees the write. Always assign the result back: s = append(s, v).
  7. len(string) is bytes. len("नेपाल") is 15. Count runes with utf8.RuneCountInString.
  8. Map order is random. Two runs can print a map in different orders. Sort the keys when output must be stable (tests, JSON you compare).
  9. Copying a struct copies its slice HEADER, not the elements. Both copies still share the elements.
