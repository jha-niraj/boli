What Go is, in one paragraph

Go is a compiled, statically typed language from Google (2009). Compiled means your source becomes one native executable before it runs: no Node, no runtime to install on the server. Statically typed means every variable has a type known at compile time, like TypeScript, except the types are not erased: the compiler uses them to lay out memory. It has a garbage collector, so you never free memory yourself. And concurrency is built into the language (goroutines and channels, Chapter 11).

Why it suits a gateway like ours: an HTTP server in Go is a few lines of the standard library, each request runs in its own cheap goroutine, the whole service ships as one file of a few MB, and it starts in milliseconds.

The first program, and the real run

Gate 1 of the service is a small program that prints Boli's price list. It lives at cmd/gateway/main.go. You will read every line of it properly in Chapter 1; for now look at the shape.

Three things to notice. Every Go program starts at func main() in package main. The import bolihq.com/gateway/internal/boli is our own package (Chapter 2 explains the path). And 2.4 MB is the whole program including the parts of the standard library it uses: copy that file to any arm64 Mac and it runs.

TypeScript vs Go: the toolchain

The big mental shift: in TypeScript the type checker is optional (code with type errors still runs as JavaScript). In Go, a type error means there is no program at all.

Traps

  1. Unused imports and unused local variables are compile errors, not warnings. While experimenting, assign to the blank identifier (_ = x) or delete the line. gopls removes unused imports on save.
  2. go run main.go compiles only that one file. If the package has other files, you get "undefined" errors. Run the package: go run . or go run ./cmd/gateway.
  3. gofmt uses tabs for indentation and aligns comments and struct fields with spaces. Do not fight it, and do not configure your editor to convert tabs in .go files.
  4. Run commands from the module folder (apps/gateway-go, where go.mod is). From the repo root you get "go: cannot find main module".
  5. GOPATH is not where your code goes any more. Old tutorials say to put projects under ~/go/src. With modules (every project since Go 1.16) your code lives anywhere.
  6. The module cache is read-only. Do not "fix" a dependency by editing it under ~/go/pkg/mod; use a replace line in go.mod if you ever must.
