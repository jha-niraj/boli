Chapter 3 - Functions and type hints

A function is a named block of code. Python marks the block with a colon and indentation instead of braces.

Python
def seconds(frames, rate):
    return frames / rate

seconds(32000, 16000)  # 2.0
TypeScript
function seconds(frames, rate) {
  return frames / rate;
}
seconds(32000, 16000); // 2

/ always gives a float in Python, so the answer is 2.0, not 2. Use // for whole-number division.

No return means None

A function that ends without return gives back None, Python's version of undefined. return ends the function, not the program.

def log_clip(clip_id):
    print("saw", clip_id)      # prints, but returns nothing

result = log_clip("03-027")
print(result)                  # None
TrapPrinting is not returning. A function that prints a number hands back None to whoever called it.

Default values and keyword arguments

Defaults work like TypeScript's rate = 16000. Callers can also name arguments, in any order.

def frames_to_seconds(frames: int, sample_rate: int = 16_000) -> float:
    return frames / sample_rate

frames_to_seconds(48000)                       # 3.0, uses the default
frames_to_seconds(48000, 48_000)               # 1.0
frames_to_seconds(sample_rate=8000, frames=8000)  # 1.0, names in any order

Two rules: parameters with defaults come after the ones without, and in a call, positional arguments come before named ones. f(sample_rate=8000, 8000) is a SyntaxError.

16_000 is just 16000. Underscores in numbers are for your eyes only.

Type hints are notes, not checks

frames: int and -> float look like TypeScript types, but Python ignores them at run time. They help your editor and tools like mypy. Nothing stops a wrong value going in.

def double(x: int) -> int:
    return x * 2

double("ab")   # "abab", no error at all

An int is accepted where a float is hinted, because Python treats every int as a valid float.

Returning several values

Python returns a tuple and the caller unpacks it. This is how split_clip_id in lesson 3 works.

def split_clip_id(clip_id: str) -> tuple[int, int]:
    part, number = clip_id.split("-")   # ["03", "027"] unpacked into two names
    return int(part), int(number)       # the comma makes a tuple

part, n = split_clip_id("03-027")       # part = 3, n = 27
TrapUnpacking needs the exact count. "03-027-b".split("-") has three pieces, so part, number = ... raises ValueError: too many values to unpack.

Guard first, then work

The Python habit is to check bad input at the top and raise, then do the real work unindented.

def real_time_factor(processing_seconds: float, audio_seconds: float) -> float:
    if audio_seconds <= 0:
        raise ValueError(f"audio_seconds must be positive, got {audio_seconds}")
    return processing_seconds / audio_seconds

real_time_factor(2.0, 10.0)   # 0.2 - five times faster than real time
Why Boli caresReal-time factor (RTF) is how we compare models on the Mac CPU in Phase 1. Below 1.0 means a model transcribes faster than the audio plays. The plan targets small RTFs on CPU.

The mutable default trap

A default value is created once, when Python reads the def, not on every call. A list default is shared between all calls.

def add_clip(clip, clips=[]):     # one list, made once
    clips.append(clip)
    return clips

add_clip("a")    # ['a']
add_clip("b")    # ['a', 'b']  - surprise

def add_clip(clip, clips=None):   # the fix
    if clips is None:
        clips = []
    clips.append(clip)
    return clips

This is the same aliasing idea from Chapter 2: one list, two names pointing at it. Use None as the default for lists and dicts.

*args and **kwargs

A star collects extra positional arguments into a tuple; two stars collect extra named ones into a dict. You will see them in library code more than you write them.

def total(*durations):
    return sum(durations)

total(1.5, 2.5, 3.0)                # 7.0, durations = (1.5, 2.5, 3.0)

def tag(clip_id, **meta):
    return {"id": clip_id, **meta}

tag("03-027", speaker="niraj", noisy=True)
# {'id': '03-027', 'speaker': 'niraj', 'noisy': True}

The same stars also spread: total(*[1.0, 2.0]) is like TypeScript's total(...[1, 2]).

lambda and key=

lambda x: expr is a one-expression arrow function. Its main job is the key= argument of sorted, max and min, which says what to compare.

clips = ["03-001", "01-104", "02-027"]
sorted(clips, key=lambda c: int(c.split("-")[1]))
# ['03-001', '02-027', '01-104']  sorted by the number after the dash

wer = {"kriti": 0.32, "conformer": 0.34, "whisper": 0.96}
max(wer)                  # 'whisper'  - compares KEYS alphabetically
min(wer, key=wer.get)     # 'kriti'    - compares the values, returns the key
Trap (your weak spot)Looping over a dict, or passing it to max, uses its keys. To get the key with the best value, pass key=d.get.

Scope

A function can read a name from outside it. But if it assigns to that name anywhere, Python treats the name as local for the whole function.

count = 0

def bump():
    count += 1       # assignment makes count local here...

bump()               # UnboundLocalError: cannot access local variable 'count'

The clean fix is to pass the value in and return the new one: count = bump(count). global count exists but is a smell.

Docstrings

The string on the first line of a function is its documentation. Your lesson stubs use them as the spec. help(frames_to_seconds) prints it.

def frames_to_seconds(frames: int, sample_rate: int = 16_000) -> float:
    """Convert a frame count to seconds.

    >>> frames_to_seconds(32_000)
    2.0
    """

Chapter 4 - Control flow, errors and stack traces

Truthiness

if accepts any value. These count as false; everything else is true.

Falsy in PythonDifferent from TypeScript?
False, None, 0, 0.0, ""Same idea as JS
[], {}, set(), ()Yes. An empty list is truthy in JS, falsy in Python
"0", "False", " "Truthy in both - a non-empty string is true
clips = []
if not clips:
    print("nothing recorded yet")   # runs - the idiomatic empty check

if, elif, and, or

if rtf < 1:
    label = "faster than real time"
elif rtf == 1:
    label = "real time"
else:
    label = "too slow"

ok = 0 < rtf < 1                  # comparisons chain, like maths
speaker = name or "unknown"       # or returns the first truthy operand
label = "long" if seconds > 10 else "short"   # Python's ternary

Words replace symbols: and, or, not instead of &&, ||, !. or returns a value, not just True/False, exactly like JS ||.

Check for None with is: if x is None. is asks "same object?", == asks "equal value?". Use is only for None, True, False.

Loops

Python's for is always a "for each". For indexes, use enumerate; to walk two lists side by side, zip.

for clip in clips:                       # for (const clip of clips)
    ...

for i, clip in enumerate(clips, start=1):  # 1 03-001, 2 03-002 ...
    print(i, clip)

for ref, hyp in zip(references, hypotheses):  # pairs; stops at the shorter list
    ...

list(range(5))         # [0, 1, 2, 3, 4]  - end excluded
list(range(0, 10, 3))  # [0, 3, 6, 9]
while retries < 3:
    retries += 1        # no ++ in Python

for clip in clips:
    if clip.endswith("-bad"):
        continue        # skip to the next clip
    if clip == "stop":
        break           # leave the loop
Trapzip drops the leftovers silently. If you have 726 FLEURS references and 725 hypotheses, zip gives 725 pairs and no warning. zip(a, b, strict=True) raises instead - use it in the eval scorer.

Exceptions

Python uses try/except where TypeScript uses try/catch. You catch errors by their type.

try:
    seconds = float(row["duration"])
except KeyError:
    print("row has no duration")
except ValueError as err:
    print("not a number:", err)
else:
    print("parsed", seconds)      # runs only if nothing was raised
finally:
    print("checked one row")      # runs always
ErrorRaised by
ValueErrorRight type, wrong value: int("12a"), unpacking the wrong count
TypeErrorWrong type: "5" + 5, calling with too many arguments
KeyErrorMissing dict key: d["x"]
IndexErrorList index past the end: [1, 2][5]
FileNotFoundErrorOpening a path that does not exist (Part 2)
ZeroDivisionError1 / 0 - JS gives Infinity, Python raises
NotImplementedErrorYour lesson stubs, on purpose

Raise your own with a message that says what was wrong: raise ValueError(f"sample_rate must be 16000, got {rate}"). A custom one is a one-line class: class ClipError(Exception): pass.

Trapexcept: pass or except Exception: pass swallows every bug, including typos in your own code. Catch the specific error you expect, and only where you can do something useful about it.

Reading a stack trace

Python prints the trace oldest call first, so read it from the bottom: the last line is the error type and message, and the frame just above it is where it happened.

Traceback (most recent call last):
  File "ml/eval/score.py", line 41, in <module>
    main()
  File "ml/eval/score.py", line 33, in main
    rtf = real_time_factor(took, row["seconds"])
  File "ml/eval/timing.py", line 9, in real_time_factor
    raise ValueError(f"audio_seconds must be positive, got {audio_seconds}")
ValueError: audio_seconds must be positive, got 0.0
  1. Last line: a ValueError, and the message says a clip had 0 seconds.
  2. One frame up: our own guard raised it, on purpose. That is not the bug.
  3. Next frame up: score.py line 33 passed row["seconds"]. The bug is in the data: an empty clip.

Skip frames inside libraries (paths with site-packages) until you reach the first frame in your own code.
